# Known Fragile Areas

## "Do Not Break" Principles
- Do not remove canvas tags (`<canvas>`) or their associated Javascript. The ambient particles and starfield effects are core to the brand.
- Do not normalize typography if it removes the "Impact" font. Hardcoded font declarations exist for a reason.

- `templates/page.mystery-box.json`: Contains the Vercel iframe embed wrapped in a highly specific locked layout (`ak-mb-wrap`, `ak-mb-canvas`).

## Archive Page (ak-archive)
- `sections/ak-archive.liquid` (v6) is a self-contained folder-deck section with inline spring physics engine and particle canvas. All 18 collection cards are hardcoded with Shopify CDN image references and collection URLs stored in `data-href` attributes. Cards are `<div>` elements (not `<a>`). If collections are added/removed/renamed, the section HTML must be updated manually.
- The old 18 `image-banner-*.liquid` section files still exist in `sections/` but are no longer referenced by `templates/list-collections.json`. Do not delete them yet — they serve as rollback reference.
- **Spring engine:** The section contains a custom `springTo()` function that drives all card animations via `requestAnimationFrame`. It stores per-element state on `el._sp` (position) and `el._sv` (velocity). **v6 addition:** `springStops{}` map tracks active springs per `data-card` index — new springs cancel old ones via `stop()` function, preventing orphaned rAF loops. If cards get stuck mid-animation, check `springStops`.
- **Bottom-aligned fan stack (v6):** Cards are `position:absolute; bottom:0; height:76%` — shorter than the stage, leaving 24% headroom above. Each trailing card shifts upward by `STRIP=26px * depth` via `translateY`. No perspective/translateZ/rotateX — the stack is a flat vertical fan. `SCALE_STEP=0.018` creates subtle narrowing. 6 visible cards (VIS=6). Opacity floor 0.55. Initial layout is instant (no spring) via `layout(false,true)`. Changing `STRIP`, card `height` percentage, or `SCALE_STEP` will alter the fan appearance. The headroom is structurally guaranteed — trailing strips cannot be hidden by the front card.
- **Cassette-case skin (2026-04-07):** A CSS-only visual skin lives in a single commented block (`CASSETTE CASE SKIN`) in the `{%- style -%}` block. It adds: 8px padding on card-inner (case housing), `::before` plastic sheen, `::after` hinge line, image inset with `border-radius:3px`, wider spine-style tabs with gradient + ridge. **Revert by deleting everything between `/* ===== CASSETTE CASE SKIN =====` and `/* ===== END CASSETTE CASE SKIN ===== */`.** The skin uses CSS overrides that sit after the base rules — if the base card-inner styles are modified, the skin overrides may need to be updated. The `padding` on card-inner changes the available image area (`height: calc(100% - 8px)`); if card `height: 76%` is changed, verify the image still fills the art window.
- **Spine tabs (cassette skin):** The cassette skin overrides `.ak-archive-tab` with wider `min-width` values, gradient backgrounds, and inset box-shadow ridge. The original folder-tab rules (lines 72–95) still exist but are overridden by the cassette skin's later CSS. Tab visibility, offset, and depth-shade are still driven by `data-depth` from JS. Front card tab is still hidden via CSS `opacity:0`.
- **Div-based interaction (v6):** Cards are `<div>` with `data-href`, not `<a>` tags. `pointerdown` calls `e.preventDefault()` + `setPointerCapture(stage)` immediately. `didMove` flag (5px) separates taps from drags. Tap → `window.location.href`. Drag → spring dismiss or snap-back. No `didDrag`/`setTimeout` fragility. Arrows are fully decoupled from drag state via `e.preventDefault(); e.stopPropagation()`. `anim` has a 700ms safety timer that auto-resets if a spring callback fails.
- **Particle canvas:** `ak-archive-canvas` uses ak-top's proven pattern: dust (no shadowBlur), floaters (accent glow), simplified shooters. DPR capped to 1. IntersectionObserver cancel/restart. If particles stop rendering, check IO observer on root element.
- **Animation lock:** `anim` flag prevents overlapping transitions. v6 adds a 700ms safety timer (`animSafetyTimer`) that resets `anim=false` if the spring completion callback fails to fire. If the deck gets stuck, check `springStops` and `animSafetyTimer`.

## Collection Page Particle Background (2026-04-07)
- **`sections/ak-collection-bg.liquid` is a new shared section** providing full-viewport ambient particles for all 18 Archive-linked collection pages. Fixed-position canvas (`position: fixed; inset: 0`) with `mix-blend-mode: screen`.

## Mystery Box Release Overlay (2026-04-07, corrected same day)
- **`sections/ak-mb-release.liquid` is a JS/CSS orchestrator, not a visible section.** It renders NO HTML of its own. It controls the existing `#akMbLock` overlay inside the embed's `.ak-mb-frame` by: showing it (`display: grid`), injecting countdown timer elements into the existing lock card, blocking iframe pointer-events, and auto-unlocking when time passes. The embed section (`custom_liquid_mysterybox_embed`) is completely untouched.
- **Overlay scoped to iframe/frame only.** The existing `ak-mb-lock` uses `position: absolute; inset: 0` inside `.ak-mb-frame`. Nav/header (ak-top) and footer (ak-footer) remain accessible.
- **Target timestamp is hardcoded in JS as UTC.** `Date.UTC(2026, 3, 9, 7, 0, 0)` = Thu Apr 9, 2026 **12:00 AM** (midnight) America/Los_Angeles (PDT). To change the release time, edit the `TARGET_UTC` variable. Month is 0-indexed (3 = April).
- **Client-side enforcement only.** Can be bypassed by disabling JS, DevTools DOM manipulation, or browser clock manipulation. This is documented and accepted — stronger enforcement would require server-side logic.
- **Auto-unlock is live.** The `setInterval` ticks every second. When `Date.now() >= TARGET_UTC`, the lock overlay is hidden (`display: none`) and iframe pointer-events restored. No reload required.
- **Post-release behavior.** If the page loads after the release time, the IIFE immediately returns — no DOM manipulation, no flash. The embed's own JS keeps the lock hidden (`LOCKED_DEFAULT = false`). The section is effectively a no-op but should be removed from `page.mystery-box.json` for cleanliness after launch.
- **Countdown timer is injected via JS.** The timer elements (`.ak-mb-lock-timer`) are created by the release section's JS and inserted into the existing `.ak-mb-lock-card` before the `.ak-mb-lock-glint`. CSS for these elements lives in the release section's `{%- style -%}` block. If the release section is removed, the timer elements disappear and the lock card reverts to its original "Unlocking soon." content.
